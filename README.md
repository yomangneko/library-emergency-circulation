# 도서관 비상 대출/반납 기록 프로그램

도서관 관리 프로그램(웹)이 서버 장애로 멈췄을 때 대출 · 반납을 손으로 적는 대신,
**인터넷 없이** 바코드 스캐너로 찍어서 그날 엑셀 파일에 공통 양식으로 쌓는 윈도우 프로그램입니다.

- 설치하지 않습니다. 실행 파일 하나(`LibraryEmergency.exe`)를 두고 더블클릭합니다.
- 인터넷을 쓰지 않습니다(업데이트 확인 · 전송 · 분석 없음).

## 받기

[최신 판 내려받기 (LibraryEmergency.exe)](https://github.com/yomangneko/library-emergency-circulation/releases/latest/download/LibraryEmergency.exe)

판마다 [Releases](https://github.com/yomangneko/library-emergency-circulation/releases) 에 실행 파일의 지문(SHA-256)을 함께 적습니다.
받은 파일의 지문은 PowerShell 에서 이렇게 확인합니다.

```powershell
Get-FileHash .\LibraryEmergency.exe -Algorithm SHA256
```

## 쓰는 순서

1. 실행 파일을 **압축을 푼 폴더**(예: 바탕 화면의 폴더 · USB)에 두고 더블클릭합니다.
2. 모드를 고릅니다 — **F1 대출**(파랑) · **F2 반납**(빨강). 처음에는 대출 모드입니다.
3. **회원번호**를 스캔합니다 → 커서가 「도서 바코드」 칸으로 넘어갑니다.
4. **책 바코드**를 스캔합니다(스캐너가 Enter 를 보냄) → 바로 기록됩니다.
   아래 상태 줄에 회색 「기록됨 · 엑셀에 옮기는 중」이 떴다가, 엑셀에 실제로 들어가면 초록 「저장 완료」로 바뀝니다.
   엑셀 정리는 뒤에서 하므로 그날 기록이 많아도 다음 스캔을 기다리게 하지 않습니다.
5. 같은 회원의 책이 더 있으면 책만 이어서 찍습니다(회원번호는 남아 있습니다).
   다음 회원으로 넘어갈 때는 **Esc**(입력 초기화)를 누르고 회원번호부터 찍습니다.

반납도 회원번호 → 책 바코드 순서입니다.

## 기록이 쌓이는 자리

실행 파일 옆의 `exports` 폴더에 날짜별로 쌓입니다.

| 파일 | 내용 |
|---|---|
| `도서기록_YYYYMMDD.xlsx` | 그날 엑셀(시트 「대출반납기록」 · 처리시간 / 구분 / 회원번호 / 도서번호 · 맨 아래 전체 · 대출 · 반납 건수) |
| `도서기록_YYYYMMDD_일지.txt` | 그날 일지 — 스캔할 때마다 엑셀보다 **먼저** 한 줄씩 덧붙여 적는 기록. 지우거나 고치지 마세요 |

- 자정을 넘겨 켜 둔 채 쓰면 다음 날 파일로 저절로 바뀝니다.
- 예전 판이 만든 그날 엑셀 파일이 있으면 그 파일에 이어 적습니다.
  단, 예전 판(2026년 3월 판) 파일의 「구분」 칸이 「대출」 · 「반납」이 아닌 다른 말로 적혀 있으면 그 예전 줄은 건수에 들어가지 않습니다.
  그런 날은 이 프로그램을 다른 저장 폴더에 두고 새 파일로 시작하세요(예전 파일은 그대로 남겨 두세요).
- 실행 파일 옆에 폴더를 만들 수 없는 자리(읽기 전용 · 압축 파일 안에서 바로 실행)면 시작할 때 알리고 저장할 폴더를 고르게 합니다.

## 엑셀 저장이 실패했을 때 — 기록은 일지에서 되살아납니다

「오늘 엑셀 열기」로 엑셀을 열어 둔 채 스캔하면 윈도우가 파일을 잠가 엑셀에 저장할 수 없습니다.
이때도 **그 스캔은 일지에 이미 적혀 있으므로 사라지지 않습니다.**

- 아래 상태 줄에 빨간 글씨로 「일지에만 기록됨 … 엑셀 미반영 N건」이 뜨고, 목록에 「엑셀 대기」로 분홍색 줄이 보입니다.
- **엑셀을 닫으면 곧 채워집니다** — 스캔하지 않아도 몇 초 안에 밀린 줄이 일지에서 엑셀로 옮겨지고, 분홍 줄이 풀립니다.
- 프로그램 창을 닫으면 밀린 줄을 엑셀에 마저 옮긴 뒤 닫힙니다. 엑셀이 열려 있어 못 옮기면 닫기 전에
  「엑셀에 아직 N건이 없습니다」를 알리고 **「엑셀을 닫고 다시 시도」** 와 **「그냥 닫기」** 중 고르게 합니다.
  그냥 닫았다면 다음에 켤 때 최근 14일 일지에서 엑셀로 채웁니다.
- 일지조차 쓸 수 없을 때(저장 폴더 문제)는 「기록 실패」 창이 뜨고 입력이 지워지지 않습니다 — 그 스캔은 저장되지 않은 것입니다.

같은 회원 · 같은 책 · 같은 구분이 10초 안에 다시 찍히면(스캐너가 두 번 보냄 등) 기록은 하되
「방금 같은 기록이 있음」을 알려 줍니다. 실수라면 엑셀에서 그 줄을 지우면 됩니다(지운 줄을 일지가 다시 살리지 않습니다).

엑셀에 직접 적은 메모(합계 아래 · 빈 줄 · 옆 칸 · 기록 줄 사이 등)는 그대로 둡니다. 새 기록은 마지막 기록 줄 바로 다음에
끼워 적고(그 아래 것은 차례 그대로 아래로 밀림), 합계는 숫자 칸만 다시 셉니다. 메모는 건수에 들어가지 않습니다.

## 「알 수 없는 게시자」 경고가 뜨는 까닭과 넘기는 법

이 프로그램은 코드 서명 인증서(유료)로 서명하지 않았습니다. 그래서 처음 실행할 때 윈도우가
**「Windows의 PC 보호」** 창을 띄웁니다. 프로그램에 문제가 있다는 뜻이 아니라 「게시자를 확인할 수 없다」는 뜻입니다.

1. 창의 **「추가 정보」** 를 누릅니다.
2. **「실행」** 단추를 누릅니다.

받은 파일의 지문이 Releases 에 적힌 지문과 같은지 먼저 확인하면 더 안전합니다.
회사 · 구청 PC 정책으로 실행이 막혀 있으면 전산 담당에게 문의하세요.

## 만들기 · 시험 (개발용)

실행 파일은 GitHub Actions 의 윈도우 기계에서 만듭니다(`.github/workflows/build.yml`).
같은 기계에서 게이트를 통과한 뒤에만 묶고, `v` 태그를 달면 Releases 에 올라갑니다.

```bash
pip install -r requirements.txt
python -I -X utf8 tests/gates.py            # 기록 처리 게이트(화면 없이)
python -I -X utf8 tests/gates.py --windows  # 윈도우: 실제 파일 잠금 게이트 포함
python -I -X utf8 tests/gui_smoke.py shots  # 화면 스모크(윈도우에서는 사진)
python library_emergency_circulation_app.py # 직접 실행
```
